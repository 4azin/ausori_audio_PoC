## 3. 서비스 간 통신

### 클라이언트 ↔ 백엔드
- REST API (JSON)
- JWT 기반 인증 (Authorization: Bearer 헤더)

### 백엔드 ↔ AI 서버
- HTTP REST (내부망)
- 백엔드가 AI 서버에 영상 경로와 분석 요청을 전송
- AI 서버가 트랙 배치 결과(JSON)를 반환

### 백엔드 ↔ 파일 스토리지
- SDK를 통한 파일 업로드/다운로드 (Presigned URL 방식 검토)

---

## 4. 인증 플로우

```
1. 클라이언트에서 "Google로 로그인" 클릭
2. Google OAuth 2.0 인증 페이지로 리다이렉트
3. 사용자 동의 후 Google에서 authorization code 반환
4. 백엔드에서 authorization code로 Google access token 교환
5. Google API로 사용자 정보(이메일, 이름, 프로필) 가져오기
6. DB에 사용자 upsert (없으면 신규 가입, 있으면 로그인)
7. 서비스 자체 JWT(Access Token + Refresh Token) 발급
8. 클라이언트는 이후 요청에 JWT 사용
```

---

## 5. 영상 처리 플로우

```
1. 클라이언트에서 영상 파일 업로드
2. 백엔드가 파일 스토리지에 저장 → 저장 경로(URL) 획득
3. 백엔드가 AI 서버에 분석 요청 (영상 URL 전달)
4. AI 서버가 영상 분석 후 6트랙 배치 결과 반환
   {
     "tracks": [
       { "type": "background", "events": [{ "start": 0.0, "end": 5.5, "soundId": "..." }] },
       { "type": "foley", "events": [...] },
       ...
     ]
   }
5. 백엔드가 분석 결과를 DB에 저장
6. 클라이언트가 웹 에디터에서 결과 확인 및 수정
7. 최종 렌더링 요청 → 완성된 영상 다운로드
```
