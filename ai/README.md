# 사운드 후반작업 보조 툴 MVP용 AI 파이프라인 수정본

## 1. 프로젝트 정의

### 서비스 한줄 정의

사용자가 **컷편집된 영상**을 업로드하면, AI가 영상의 맥락을 파악해 **사운드 큐 시트 초안**을 자동 생성하고, 내부 사운드 DB에서 후보를 추천하여 사용자가 빠르게 수정할 수 있게 하는 보조 툴이다.

### MVP 목표

MVP의 목표는 **완벽한 자동 싱크/믹싱**이 아니라 아래 두 가지다.

1. 영상 전체를 이해하고 **트랙별 사운드 초안**을 생성한다.
2. 사용자가 바로 수정 가능한 **큐 시트 + 추천 후보군**을 제공한다.

즉, MVP는 “원클릭 완성”보다 **원클릭 초안 생성**에 가깝다.

---

## 2. MVP 전제

### 입력

* 사용자 입력: **영상 파일 1개**
* 대상 영상: **최대 3분 / 1080p**
* 기본 전제: 컷편집은 이미 끝난 상태

### 출력

* 전체 영상에 대한 메타 정보
* 트랙별 사운드 큐 시트 JSON
* 각 이벤트별 추천 사운드 후보군
* 프론트 수정용 타임라인 데이터

### 이번 단계에서 의도적으로 제외하는 것

아래는 MVP 범위에서 제외하거나 단순화한다.

* 원본 오디오 정밀 분석
* 스크립트 / 자막 입력 활용
* 프레임 단위 완벽 싱크 보장
* 자동 최종 믹스 렌더링
* 복잡한 리소스 최적화 / 비용 최적화
* 과도한 재시도 / 고급 워커 스케줄링

---

## 3. 설계 원칙

### 3-1. 큐 시트 중심

AI의 1차 목적은 “영상을 사운드적으로 해석한 결과”를 **큐 시트 형태로 구조화**하는 것이다.

즉:
`video -> scene/event understanding -> sound cue sheet -> sound retrieval -> editable timeline`

### 3-2. Soft 계열과 Hard 계열 분리

모든 사운드를 같은 방식으로 처리하지 않는다.

* **Soft 성격**

  * ambience
  * music
  * cinematic drone / riser
  * vo/narration 제안
  * 일부 맥락형 SFX

* **Hard 성격**

  * foley
  * 타격형 SFX
  * 순간 강조 cinematic hit / whoosh

이 분리는 유지하는 게 좋다. 다만 MVP에서는 Hard 성격도 **정밀 자동 싱크**가 아니라 **러프한 이벤트 초안 생성**까지를 목표로 한다.

### 3-3. 자동화보다 편집 가능성 우선

MVP에서 중요한 것은 AI가 다 맞추는 것이 아니라,
**사용자가 빠르게 고치기 쉬운 결과를 내놓는 것**이다.

따라서 최종 산출물은 렌더된 오디오가 아니라 **수정 가능한 JSON 타임라인**이어야 한다.

## 4. 전체 시스템 구조

## 4-1. 권장 구조

### 메인 서버 + Python AI Worker 분리

질문했던 부분에 답하면, **영상 분석용 Python 서버는 따로 두는 게 맞다.**

이유는 간단하다.

* 영상 처리, 프레임 추출, LLM 호출, 임베딩, 검색은 Python 생태계가 훨씬 편하다.
* 메인 서버는 업로드, 상태 관리, 결과 저장, 프론트 응답에 집중하는 게 낫다.
* 분석 시간이 길 수 있으므로 웹 요청-응답과 분리하는 편이 안정적이다.

### 최소 구성

* **Main Server**

  * 업로드 관리
  * 작업 생성
  * 작업 상태 조회
  * 결과 JSON 저장/전달

* **Python AI Worker**

  * 영상 전처리
  * 프레임 추출
  * LLM 추론
  * 큐 시트 생성
  * 벡터 검색
  * 결과 JSON 패키징

### MVP 추천 방식

복잡한 MSA까지 갈 필요는 없다. 우선은 아래면 충분하다.

* Main Server가 분석 Job 생성
* Python Worker가 Job polling 또는 queue 구독
* 처리 완료 후 결과를 DB/S3에 저장
* 프론트는 상태 조회

즉, **“분리하되 단순하게”** 가 맞다.

## 5. MVP AI 파이프라인

# Phase 0. 업로드 및 작업 생성

사용자가 영상을 업로드하면 메인 서버가 분석 작업을 생성한다.

### 생성 정보 예시

* `project_id`
* `video_url`
* `status = queued`
* `duration`
* `resolution`

### 작업 상태

MVP에서도 최소한 아래 상태는 있어야 한다.

* `queued`
* `preprocessing`
* `analyzing_soft`
* `analyzing_hard`
* `retrieving`
* `done`
* `failed`

이건 리소스 최적화가 아니라 **사용자 UX** 때문에 필요하다.

---

# Phase 1. 전처리

## 5-1. 프레임 추출

* 도구: `ffmpeg`
* 기본 추출:

  * 전체 맥락용: `1fps`
  * 컷 분석용: shot 단위 대표 프레임 또는 짧은 구간 프레임

### 왜 필요한가

기존 원안의 “전체 영상을 멀티모달 LLM에 넣는다”는 방향은 맞지만,
실제로는 **원본 영상을 그대로 보내는 것보다 프레임 기반으로 구조화해서 보내는 편이 더 안정적**이다.

## 5-2. 컷/씬 구간 추정

여기는 원안에서 보완이 필요한 부분이다.

LLM에게 무조건 전체 영상을 한 번에 던지기보다,
전처리 단계에서 **대략적인 컷/씬 경계**를 먼저 잡아두는 게 좋다.

MVP에서는 무거운 모델까지 쓸 필요 없이 아래 중 하나면 충분하다.

* ffmpeg scene detection
* 프레임 간 차이 기반 간단한 컷 변화 탐지

### 역할

이 값은 정확한 편집 정보가 아니라 **LLM에게 줄 보조 정보**다.

즉:

* 어느 구간이 장면 전환인지
* 어느 구간이 비슷한 맥락인지
* 어디서 큐 시트를 나누면 좋은지

를 도와준다.

---

# Phase 2. 전체 영상 맥락 분석 (1차 글로벌 분석)

이 단계는 기존 원안의 장점을 그대로 살린다.

## 목표

영상 전체를 보고 아래를 먼저 뽑는다.

* 영상 종류
* 전체 분위기
* 주요 공간/환경
* 주요 행동 유형
* 전체 사운드 방향성

## 입력

* 3~5초 간격 샘플 프레임
* 전체 길이 정보
* 컷/씬 변화 정보 요약

## 모델

* 멀티모달 LLM (`gemini-2.5-flash` 가정)

## 출력 예시

```json
{
  "video_type": "브이로그",
  "genre": "일상/라이프스타일",
  "mood": ["밝음", "경쾌함", "도시적"],
  "main_spaces": ["카페", "거리", "실내"],
  "sound_direction": {
    "ambience": "생활 배경음 위주",
    "music": "가벼운 로파이/어쿠스틱 계열",
    "foley_density": "medium",
    "cinematic_density": "low"
  }
}
```

### 살려야 하는 점

이 글로벌 분석은 꼭 유지하는 게 좋다.
이게 있어야 뒤 단계에서 트랙별 판단이 흔들리지 않는다.

---

# Phase 3. Soft 트랙 큐 시트 생성 (1 cycle)

이 단계는 MVP에서 가장 먼저 사용자에게 보여줄 수 있는 핵심 결과다.

## 대상 트랙

* ambience
* music
* cinematic
* vo/narration 제안
* 맥락형 SFX

## 방식

1fps 프레임과 컷/씬 정보를 바탕으로,
영상 전체를 장면 단위로 나누어 **구간 중심 큐 시트**를 생성한다.

## 이 단계의 목표

정밀도가 아니라 **맥락에 맞는 구간 배치 초안**이다.

## 출력 단위

이벤트 1개당 아래 구조를 가진다.

```json
{
  "event_id": "soft_001",
  "track": "ambience",
  "category_path": ["Ambience", "Interior", "Cafe"],
  "start_time": 0.0,
  "end_time": 18.5,
  "description": "조용한 카페 내부의 잔잔한 생활 배경음",
  "confidence": 0.86
}
```

## 보완 포인트

원안에서는 `SFX`가 여기에도 들어가고, 뒤에도 들어가서 살짝 애매했다.
MVP에서는 아래처럼 정리하는 게 좋다.

* **Soft 단계의 SFX**

  * 장면 맥락을 보조하는 넓은 의미의 효과
  * 예: 군중 웅성거림, 먼 차량 소리, 공간성 강조 효과

* **Hard 단계의 SFX**

  * 순간 타격/동작과 맞아야 하는 효과
  * 예: 문 닫힘, 물건 충돌, 유리 파손

즉, **SFX를 성격 기준으로 나눠서 취급**한다.

---

# Phase 4. Soft 트랙 구간 재검증 (2 cycle)

원안의 2 cycle 구조는 살리는 게 좋다.
다만 MVP에서는 “정밀 보정”이 아니라 **오답 감소용 검증 단계**로 보는 것이 적절하다.

## 입력

* 1차 큐 시트의 각 구간
* 해당 구간 trim 영상
* 1차 context set

## 목표

* category_path가 맞는지
* 시작/종료 구간이 너무 넓거나 좁지 않은지
* description이 검색 가능한 수준으로 충분한지

## 수정 결과

* 타임스탬프 미세 조정
* category_path 수정
* confidence 보정
* description 보강

### 중요한 점

이 단계의 목적은 “완벽한 분류”가 아니라
**검색 가능한 품질의 context set 완성**이다.

---

# Phase 5. Hard 트랙 초안 생성

여기가 원안에서 가장 보완이 필요한 부분이다.

기존 원안은 foley를 매우 세세하게 잡는 방향인데,
MVP에서는 이 목표를 조금 낮춰야 한다.

## 대상

* foley
* 타격형 SFX
* 순간성 cinematic hit / whoosh

## 목표

프레임 단위 완벽 싱크가 아니라,
**컷/짧은 구간 단위의 이벤트 초안**을 많이 뽑아주는 것.

즉:

* 놓치는 것보다 조금 많이 뽑는 쪽이 낫다.
* 사용자가 mute/remove 할 수 있게 한다.

## 입력

* 컷 단위 혹은 짧은 구간 영상
* 글로벌 맥락 정보
* 장면 유형 정보

## 출력 예시

```json
{
  "event_id": "hard_014",
  "track": "foley",
  "category_path": ["Foley", "Footstep", "Concrete"],
  "start_time": 12.20,
  "end_time": 12.80,
  "description": "인물이 콘크리트 바닥을 걸으며 착지하는 발소리",
  "confidence": 0.61
}
```

## MVP에서 중요한 운영 원칙

* foley는 **많이 뽑되 confidence를 함께 준다**
* confidence가 낮아도 버리지 않고 초안에 남길 수 있다
* 사용자가 쉽게 제거할 수 있어야 한다

## 원안 대비 수정 포인트

원안에서는 “전문 사운드 후반작업자 마인드로 세세하게”가 목표인데,
이건 장기적으로 맞다.
하지만 MVP에서는 다음처럼 바꾸는 것이 현실적이다.

**기존**

* 매우 정밀한 foley 큐 시트 작성

**MVP 수정**

* 컷/행동 기반의 러프한 foley 이벤트 제안
* 시작/종료 범위는 약간 넓어도 허용
* 이후 프론트 수정 전제

# Phase 6. 사운드 검색

## 핵심 원칙

LLM이 곧바로 wav를 고르는 것이 아니라,
**큐 시트의 context set을 바탕으로 DB에서 후보군을 검색**한다.

## 검색 방식

* `category_path`로 1차 필터
* `description` 임베딩으로 유사도 검색
* 최종 후보 상위 N개 반환

## 왜 필요한가

이 부분은 기존 문서 방향이 좋다.
카테고리 필터 없이 벡터 검색만 쓰면 엉뚱한 소리가 나올 수 있다.

## MVP 권장 방식

Top 1만 확정하지 말고 **Top 3~5 후보**를 남기는 게 좋다.

출력 예시:

```json
{
  "event_id": "soft_001",
  "recommended_assets": [
    {
      "asset_id": "amb_cafe_023",
      "score": 0.91
    },
    {
      "asset_id": "amb_cafe_041",
      "score": 0.87
    },
    {
      "asset_id": "amb_interior_012",
      "score": 0.82
    }
  ]
}
```

### 이건 꼭 보완해야 함

원안에는 “적절한 후보군을 뽑아 추천” 방향이 있었는데,
이걸 명세에 더 명확히 적는 게 좋다.

MVP의 핵심은 **자동 1개 선택 + 대체 후보 유지**다.

# Phase 7. 결과 패키징

최종 결과는 “오디오를 완성해서 내려주는 것”보다
**프론트에서 편집 가능한 구조로 전달하는 것**이 중요하다.

## 최종 JSON에 들어가야 할 것

* 전체 영상 메타
* soft track cue sheet
* hard track cue sheet
* 각 이벤트별 추천 후보군
* confidence
* UI 그룹 정보

## 권장 JSON 구조

```json
{
  "project_id": "p_001",
  "video_summary": {
    "video_type": "광고",
    "mood": ["세련됨", "빠름"],
    "main_context": "도심 실내외를 오가는 템포감 있는 라이프스타일 광고"
  },
  "tracks": [
    {
      "track_name": "ambience",
      "events": []
    },
    {
      "track_name": "music",
      "events": []
    },
    {
      "track_name": "foley",
      "events": []
    },
    {
      "track_name": "sfx",
      "events": []
    },
    {
      "track_name": "cinematic",
      "events": []
    }
  ]
}
```

## subLayers 구조

같은 시간대에 겹치는 소리들은 하나의 이벤트 그룹으로 묶을 수 있어야 한다.

예:

* 유리창 파손
* 파편 낙하
* 인물 반응성 whoosh

이런 경우는 프론트에서 펼쳐서 수정할 수 있도록
`subLayers` 구조를 두는 게 좋다.

## 6. 기존 원안에서 살릴 부분

아래는 꼭 살리는 게 좋다.

### 6-1. 전체 영상 맥락 파악 우선

이건 맞는 접근이다.
사운드는 장면 단위의 맥락을 먼저 알아야 한다.

### 6-2. 1 cycle + 2 cycle 구조

처음부터 한 번에 완벽히 뽑기보다,
1차 생성 후 구간 재검증하는 구조는 유지할 가치가 있다.

### 6-3. 1번과 2번 병렬 진행

UX 관점에서 아주 좋다.

즉,

* Soft 결과를 먼저 보여주고
* 사용자는 먼저 수정 시작
* 뒤에서 Hard/foley 분석 완료 후 추가 반영

이 흐름은 제품적으로 강점이다.

### 6-4. “최대한 많은 context를 뽑고 사용자가 제거”

foley 같은 어려운 영역에서는 이 철학이 맞다.

---

## 7. 기존 원안에서 수정이 필요한 부분

### 7-1. “전체 영상을 LLM에 보낸다”는 표현

방향은 맞지만 구현 문서에는 더 구체적으로 써야 한다.

권장 표현:

* 원본 영상 전체를 그대로 보내기보다
* 전처리한 프레임/구간 데이터를 기반으로 분석한다

### 7-2. foley의 정밀도 목표

MVP에서 너무 높다.

권장 수정:

* “프레임 단위 정확한 자동 싱크” 대신
* “행동 기반 러프 큐 시트 생성”으로 낮춘다

### 7-3. SFX 정의 중복

Soft와 Hard 모두에 SFX가 등장하므로
**맥락형 SFX / 타격형 SFX**로 나눠 정의해야 한다.

### 7-4. 큐 시트와 검색의 연결 정의 부족

큐 시트를 만들고 끝나는 게 아니라,
각 이벤트가 검색 시스템에 바로 연결되도록
`category_path`, `description`, `confidence`를 표준 필드로 고정하는 것이 좋다.

## 8. MVP에서 추가로 넣어야 하는 누락 요소

### 8-1. 컷/씬 경계 정보

이건 꼭 넣는 게 좋다.
LLM이 장면을 더 안정적으로 나누게 도와준다.

### 8-2. 작업 상태 관리

UX 때문에 필요하다.

### 8-3. confidence 기준

이벤트마다 confidence를 꼭 저장해야 한다.

예:

* 0.8 이상: 자동 추천 강함
* 0.5~0.8: 일반 후보
* 0.5 미만: 프론트에서 기본 mute 상태로 둘 수도 있음

### 8-4. 후보군 반환

자동 선택 1개만 주지 말고 대체 후보를 남긴다.

### 8-5. 비파괴 편집 구조

최종 산출물을 렌더 파일이 아니라 편집 가능한 JSON으로 고정한다.

## 10. 최종 제안 문구

아래 문구로 프로젝트 방향을 정리하면 꽤 명확합니다.

> 본 MVP의 목표는 컷편집된 영상을 입력받아, 전체 영상 맥락 분석을 기반으로 트랙별 사운드 큐 시트 초안을 자동 생성하고, 내부 사운드 DB에서 적절한 후보군을 추천하여 사용자가 빠르게 수정할 수 있는 편집 가능한 타임라인 JSON을 제공하는 것이다.
>
> 분석은 Soft 성격의 트랙(ambience, music, cinematic, 맥락형 SFX)과 Hard 성격의 트랙(foley, 타격형 SFX)을 분리하여 병렬 수행하며, Soft 결과를 우선 제공해 사용자 작업을 먼저 시작할 수 있게 하고, Hard 결과는 후속 비동기 분석으로 추가 제공한다.
>
> Python 기반 AI Worker는 메인 서버와 분리하여 운영하며, MVP 단계에서는 영상 기반 분석과 큐 시트 생성, 후보 검색, JSON 패키징에 집중하고, 정밀 싱크·고급 믹싱·원본 오디오 활용은 후속 고도화 단계로 둔다.
