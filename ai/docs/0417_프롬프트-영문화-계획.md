# 프롬프트 한글 → 영문 전환 계획

> 작성일: 2026-04-17

---

## 1. 왜 영문으로 바꾸는가

- Gemini 모델은 영어 프롬프트에서 instruction following 정확도가 더 높음
- 출력이 영어면 백엔드/프론트에서 i18n 처리가 깔끔해짐
- 토큰 효율: 같은 의미를 한글보다 영어가 더 적은 토큰으로 표현 → 비용 절감
- taxonomy key가 이미 전부 영어 (Foley, Ambience, Music 등) → 프롬프트와 일관성

### 2-3. 프롬프트 내 한글 예시값

JSON 스키마 안의 예시 문자열도 영어로 교체:

| 현재 | 변경 |
|------|------|
| `"장면 한 줄 요약"` | `"One-line scene summary"` |
| `"주요 행동1"` | `"Key action 1"` |
| `"장소", "인물", "화면 변화"` | `"Location", "Characters", "Visual transition"` |
| `"생당근을 한입 베어 무는 순간..."` | `"Biting into a raw carrot..."` |
| `"카페 내부의 낮은 웅성거림..."` | `"Low murmur and gentle cup clinking..."` |
| mood 예시: `["아늑함", "일상적"]` | `["cozy", "everyday"]` |

### 2-4. 출력 언어 지시

각 프롬프트에 명시적으로 추가:

```
[Language]
- All output text (description, summary, context, mood, etc.) MUST be in English.
- JSON keys remain unchanged.
```

## 3. 변환하지 않는 것

| 항목 | 이유 |
|------|------|
| taxonomy.json 키 | 이미 영어 |
| JSON 필드명 (snake_case) | 이미 영어, 백엔드 계약 |
| 코드 주석/docstring | 팀 내부용, 별도 작업 |
| 로그 메시지 (`[info]`, `[upload]` 등) | 개발자용, 영향 없음 |

## 4. Langfuse 버전 관리 전략

### 4-1. 현재 구조

```
seed_prompts.py
  → analyze_global.PROMPT         → Langfuse "global_analyzer"
  → analyze_global_music.PROMPT   → Langfuse "global_music_analyzer"
  → analyze_local_foley.PROMPT    → Langfuse "foley_analyzer"
  → analyze_local_non_foley.PROMPT → Langfuse "non_foley_analyzer"
```

`seed_prompts.py`를 실행하면:
- 기존 최신 버전과 비교 → 내용이 다르면 새 버전 생성
- `--label production` (기본) 또는 `--label staging`으로 라벨 지정

### 4-2. 영문 전환 시 버전 관리 흐름

```
Step 1: 코드에서 PROMPT 상수를 영문으로 교체
Step 2: python seed_prompts.py --label staging --dry-run
        → 4개 프롬프트 모두 "변경됨" 확인
Step 3: python seed_prompts.py --label staging
        → Langfuse에 staging 라벨로 새 버전 업로드
Step 4: .env에서 테스트 시 staging 프롬프트 사용하도록 설정 (선택적)
Step 5: 파이프라인 실행 → Langfuse에서 결과 품질 확인
Step 6: 품질 OK → python seed_prompts.py --label production
        → production 라벨로 승격
```

### 4-3. Langfuse 프롬프트 버전 히스토리 예시

```
global_analyzer
  v1 (한글, production)    ← 기존
  v2 (영문, staging)       ← Step 3
  v2 (영문, production)    ← Step 6 (라벨 이동)

foley_analyzer
  v1 (한글, production)
  v2 (영문, staging)
  v2 (영문, production)
```

### 4-4. 런타임 프롬프트 로딩

`llm_client.get_prompt()`가 Langfuse에서 `label=production`을 가져옴.
Langfuse 미연결 시 코드 내 PROMPT 상수(fallback)를 사용.

→ **코드의 PROMPT 상수 = 최신 영문 버전과 항상 동기화** 유지 필수.

## 5. 작업 순서

```
1. PROMPT 상수 영문화 (4개 파일)
   - analyze_global.py
   - analyze_global_music.py
   - analyze_local_foley.py
   - analyze_local_non_foley.py

2. context f-string 영문화 (4개 파일)
   - [영상 정보] → [Video Info]
   - [Scene 메타데이터] → [Scene Metadata]

3. seed_prompts.py로 staging 업로드
   $ python seed_prompts.py --label staging --dry-run
   $ python seed_prompts.py --label staging

4. 테스트 실행 (짧은 영상)
   $ python analyze_global.py 테스트영상.mp4 --out output/en_test_global.json
   $ python analyze_local_foley.py 테스트영상.mp4 --result output/en_test_global.json --out output/en_test_foley.json
   $ python analyze_local_non_foley.py 테스트영상.mp4 --result output/en_test_global.json --out output/en_test_non_foley.json

5. 결과 검증
   - JSON 필드값이 전부 영어인지
   - taxonomy path가 유효한지
   - description 품질이 한글 대비 동등 이상인지
   - Langfuse trace에서 prompt version이 v2(staging)로 찍히는지

6. production 승격
   $ python seed_prompts.py --label production
```

## 6. 영문화 시 주의사항

### 6-1. description 품질

한글 프롬프트에서 "구체적으로 서술하라"는 지시가 잘 작동하고 있었음.
영문 전환 시 동일 수준의 구체성을 유지하도록 예시를 충분히 포함:

```
[Description Rules]
- Be specific and concrete. Describe WHAT object, WHAT action, and WHEN the sound occurs.
- Bad:  "Cafe background sound"
- Good: "Low murmur of conversations mixed with gentle cup clinking inside a cafe. Creates a cozy, lived-in atmosphere."
```

### 6-2. mood 키워드

현재 한글 mood (`["아늑함", "일상적"]`)를 영어로 통일하면 백엔드에서 일관된 처리 가능:

```
- mood keywords MUST be in English.
- Examples: ["cozy", "warm"], ["tense", "cold"], ["bright", "cheerful"]
```

### 6-3. Foley description 예시

```
- Bad:  "Chewing sound"
- Good: "Biting into a raw carrot with a short, crisp crunch at the moment of contact."
```
